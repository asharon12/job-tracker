Data Models

👤 User

  • id, name, email, passwordHash
  • createdAt
  • → applications, resumes, notifications

📋 Application

  • companyName, jobTitle, jobUrl
  • status: APPLIED · SCREENING · INTERVIEW · OFFER · REJECTED · GHOSTED
  • jdRaw, jdSummary (JSON)
  • salaryMin, salaryMax, salaryCurrency
  • workLocation: REMOTE · HYBRID · ONSITE
  • hasReferral, refereeName, refereeRole, refereeCompany, refereeLinkedin
  • appliedDate, deadlineDate, notes
  • → resume, interviewRounds, notifications

📄 Resume

  • name, fileUrl, fileName
  • uploadedAt
  • → applications

🎯 InterviewRound

  • roundNumber, roundType
  • type: HR_SCREEN · OA · DSA · SYSTEM_DESIGN · BEHAVIORAL · CASE_STUDY · OTHER
  • scheduledDate, notes
  • outcome: PENDING · PASSED · FAILED · CANCELLED

🔔 Notification

  • type: DEADLINE_REMINDER · FOLLOW_UP
  • message, isRead
  • triggerDate, createdAt
  • → user, application

Notification System
⏰
Deadline Reminder
Fires N days before deadlineDate. Cron checks daily at 8 AM. Deduplication ensures one notification per application per trigger window.
📅
Interview Day Reminder
Fires on the day of a scheduled InterviewRound.scheduledDate. Cron checks daily at 8 AM.
🔔
Delivery
In-app only. Stored in DB. Frontend fetches on page load. Bell icon shows unread badge count. Clicking marks as read.
Key Data Flows

Create Application + JD Summary

1
User fills form → POST /api/applications
2
User pastes JD text → POST /api/applications/:id/summarize-jd
3
Gemini returns structured JSON (skills, responsibilities, tech stack, work location)
4
Saved to jdSummary column → rendered as bullet points in table row

Resume Upload

1
POST /api/resumes with multipart/form-data
2
multer streams file → Cloudinary stores PDF
3
DB stores fileUrl, fileName, name linked to user
4
User links resume to an application via resumeId on create/edit

Notification Flow

1
Cron fires daily at 8 AM → checks deadlines and interview dates across all users
2
Writes Notification rows to DB (deduplicated)
3
Frontend fetches GET /api/notifications on page load
4
Bell badge shows unread count; click to mark as read

Auth Flow

1
Register / Login → server returns JWT token
2
Token stored in Zustand (persisted to localStorage)
3
Every API request sends Authorization: Bearer <token>
4
Auth middleware validates token, attaches userId to request
