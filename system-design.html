Data Models

👤 User

  • id, name, email, passwordHash
  • createdAt
  • → applications, resumes, notifications

📋 Application

  • companyName, jobTitle, jobUrl
  • status: APPLIED · SCREENING · INTERVIEW · OFFER · REJECTED · GHOSTED
  • jdRaw, jdSummary (JSON)
  • salaryMin, salaryMax, salaryCurrency
  • workLocation: REMOTE · HYBRID · ONSITE
  • hasReferral + referee fields
  • appliedDate, deadlineDate, notes
  • → resume, interviewRounds, notifications

📄 Resume

  • name, fileUrl, fileName
  • uploadedAt
  • → applications

🎯 InterviewRound

  • roundNumber, roundType
  • HR_SCREEN · OA · DSA · SYSTEM_DESIGN · BEHAVIORAL · CASE_STUDY · OTHER
  • scheduledDate, notes
  • outcome: PENDING · PASSED · FAILED · CANCELLED

🔔 Notification

  • type: DEADLINE_REMINDER · FOLLOW_UP
  • message, isRead
  • triggerDate, createdAt
  • → user, application

Notification System
⏰
Deadline Reminder
Pre-scheduled 3 days before deadlineDate. Created when application is saved. Old future unread notifications deleted before re-creating (deduplication).
📅
Interview Day Reminder (FOLLOW_UP)
Scheduled for 8 AM on the day of each InterviewRound.scheduledDate. Created per round when rounds are added/updated.
🗑️
Cleanup Cron (daily 8 AM)
Deletes read notifications older than 30 days to keep the DB clean.
🔔
Delivery
In-app only. Stored in DB. Frontend fetches GET /api/notifications every 60 seconds. Bell badge shows unread count. Click to mark as read.
Key Data Flows

Auth Flow

1
Register / Login → POST /api/auth/register|login
2
Server returns { token, user } → stored in Zustand + localStorage
3
Every API request adds Authorization: Bearer <token>
4
401 response → token cleared → redirect to /login

JD Summarization

1
User pastes JD text into application form
2
POST /api/applications/:id/summarize-jd
3
Gemini 1.5 Flash returns structured JSON (skills, responsibilities, tech stack)
4
Saved to jdSummary column → rendered as bullet points

Resume Upload

1
POST /api/resumes with multipart/form-data
2
multer-storage-cloudinary streams file directly to Cloudinary
3
DB stores fileUrl, fileName, name linked to user
4
User links resume to application via resumeId

Dark / Light Mode

1
User clicks Sun/Moon icon in Navbar
2
Zustand theme.store toggles isDark, persists to localStorage
3
data-theme="dark|light" set on <html> element
4
CSS variables (--bg-base, --text, --border etc.) switch values

Changelog
feat
Dark / Light mode toggle
Added Zustand theme store (persisted). Sun/Moon button in Navbar. CSS custom properties (--bg-base, --text, --border etc.) switch via data-theme attribute on <html>. Theme remembered across sessions.
infra
Deployed to Vercel + Render + Neon
Frontend on Vercel (free Hobby plan), backend on Render (free web service), database on Neon (serverless PostgreSQL free tier). SPA routing fixed via vercel.json rewrites in frontend/ directory.
ci
GitHub Actions CI pipeline
backend.yml and frontend.yml — type check + build gate on every push/PR. Runs on Node 22. Backend adds prisma generate before tsc. Frontend uses --legacy-peer-deps. Deploy handled natively by Vercel/Render.
fix
Replaced axios with native fetch
axios module-level initialization caused a blank screen in Vite 7's esbuild bundler. Replaced with a native fetch wrapper in api.ts. All hooks updated to remove .then(r => r.data) (axios response unwrapping).
fix
import type for all TypeScript interfaces
Vite's esbuild processes files in isolation (like isolatedModules). TypeScript interfaces compiled to nothing — bare imports failed at runtime with "does not provide an export named X". Fixed by changing all type-only imports to import type { ... }.
fix
CalendarPage: replaced globalizeLocalizer with dateFnsLocalizer
globalizeLocalizer(Globalize) runs at module level and requires CLDR data — crashed on load. Replaced with dateFnsLocalizer using date-fns v3 subpath imports (date-fns/format, date-fns/parse etc.).
fix
Vite downgrade to v7 (Node 22.10.0 compatibility)
Vite 8 requires Node ≥22.12.0. Local machine runs Node 22.10.0. Downgraded to Vite 7 which supports Node 20.19+.
fix
Removed date-fns from all components
date-fns v4/v3 caused module-level crashes in specific import paths. Replaced all usages with native Intl / toLocaleDateString in a shared dates.ts utility.
infra
Added .npmrc (legacy-peer-deps) to frontend and backend
Vercel and Render run plain npm install which fails on peer dependency conflicts (eslint, multer-storage-cloudinary). .npmrc with legacy-peer-deps=true fixes this without --force.
