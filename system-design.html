Key Architectural Points

  • Vite proxy in dev: Frontend (port 5174) proxies /api to backend (port 3001). In prod, VITE_API_URL is set to the Render URL so requests go directly.
  • JWT stateless auth: No sessions. Token stored in localStorage via Zustand persist. Every request sends Authorization: Bearer <token>. 401 → auto-redirect to /login.
  • Prisma db push (no migrations): Schema changes applied with prisma db push locally. No migration files committed. Neon prod is updated manually before deploy.
  • Notifications are pre-scheduled: Not delivered in real time. When an application or round is saved, future notification records are written to DB with a triggerDate. The frontend polls GET /api/notifications every 60 seconds — the endpoint only returns records where triggerDate ≤ now.
  • Recharts + CSS vars limitation: SVG fill/stroke attributes can't use CSS variables directly. Dashboard charts use useThemeStore to read isDark and pass computed hex colors to Recharts props.
  • Mobile layout — Sidebar replaced by BottomNav: On small screens (md: breakpoint = 768px) the Sidebar is hidden (hidden md:flex). A fixed bottom navigation bar (BottomNav.tsx, md:hidden) provides 5-tab navigation instead. Desktop layout is entirely unchanged. All grids use grid-cols-1 sm:grid-cols-2 patterns so content stacks on narrow screens.
  • Archive is a filtered view, not a DB state: REJECTED and GHOSTED are the "archived" statuses. GET /api/applications excludes them by default (status NOT IN). Pass archived=true to get them. No schema migration needed — status is the single source of truth.
Tech Stack — Detailed

Frontend

  • React 19 + TypeScript (strict mode)
  • Vite 7 — esbuild in dev, rolldown in build. Pinned to v7 because v8 needs Node ≥22.12.0 (local is 22.10.0)
  • Tailwind CSS v4 via @tailwindcss/vite — uses CSS custom properties for theming, not Tailwind dark mode
  • React Router v7 — SPA routing, ProtectedLayout wrapper
  • TanStack React Query v5 — server state, cache invalidation on mutations
  • Zustand v5 — auth store (token + user) + theme store (isDark), both persisted to localStorage
  • React Hook Form — form state, no re-renders on every keystroke
  • Recharts — PipelineFunnel (bar), ActivityChart (line), SalaryChart (scatter)
  • React Big Calendar + date-fns v3 subpath imports
  • Lucide React — icons
  • Native fetch API — custom wrapper in api.ts (no axios)

Backend

  • Node.js + Express 4 + TypeScript
  • Prisma ORM v5 — type-safe DB queries, schema-first
  • PostgreSQL — local Homebrew postgresql@16, Neon in prod
  • JWT (jsonwebtoken) + bcryptjs for auth
  • Zod — request body validation. Schemas are partial for PATCH/PUT
  • node-cron — runs daily at 00:00 UTC to delete read notifications older than 30 days
  • Cloudinary + Multer — resume PDF upload (wired up but not exposed in current UI)
  • ts-node-dev — hot reload in development (--respawn --transpile-only)
  • dotenv, cors
Running Locally

Prerequisites

  • Node.js 22.10+ and npm
  • PostgreSQL 16 via Homebrew — brew services start postgresql@16
  • Database created: createdb jobtracker

Backend — backend/.env

  • DATABASE_URL=postgresql://<user>@localhost:5432/jobtracker
  • JWT_SECRET=any-long-random-string
  • JWT_EXPIRES_IN=7d
  • PORT=3001
  • CLIENT_URL=http://localhost:5174 ← must match Vite port exactly

Start commands

  • Backend: cd backend && npx prisma db push && npm run dev
  • Frontend: cd frontend && npm run dev
  • Port 3001 is auto-cleared before every start via the predev script in backend/package.json — no manual kill needed
  • Prisma Studio (DB GUI): cd backend && npx prisma studio
Data Models (Current Schema)

User

  • id (uuid), email (unique), passwordHash, name
  • createdAt
  • → applications, resumes, notifications

Application

  • companyName, jobTitle, jobUrl (optional)
  • status: APPLIED · AWAITING_REFERRAL · SCREENING · INTERVIEW · OFFER · REJECTED · GHOSTED
  • jdRaw (text — plain job description field, stored as-is)
  • salaryMin (Float), salaryCurrency — single salary field, no max
  • workLocation (String — free text, e.g. "San Francisco, CA" or "Remote")
  • resumeName (String — text label of resume used, e.g. "Google_SWE.pdf")
  • hasReferral (Boolean), refereeName, refereeRole, refereeCompany, refereeLinkedin
  • appliedDate, notes
  • createdAt, updatedAt (auto)
  • → interviewRounds, notifications

InterviewRound

  • roundNumber (auto-incremented per application)
  • roundType: HR_SCREEN · OA · DSA · SYSTEM_DESIGN · BEHAVIORAL · CASE_STUDY · OTHER
  • scheduledDate (DateTime — stores full datetime including time in UTC)
  • notes (optional)
  • outcome: PENDING · PASSED · FAILED · CANCELLED

Notification

  • type: FOLLOW_UP · AWAITING_REFERRAL_REMINDER
  • message (string), isRead (Boolean)
  • triggerDate — when it becomes visible to the user
  • createdAt
  • → user, application

Resume (wired, not in active UI)

  • name, fileUrl, fileName (Cloudinary)
  • uploadedAt
  • The sidebar "Build Resume" link points to an external hosted resume builder instead

Schema decisions worth remembering

FieldWhy it's this way
workLocation String?Originally an enum (REMOTE/HYBRID/ONSITE). Changed to free text so users can enter "San Francisco, CA" or any custom value.
resumeName String?Added as a plain text field. Users type the name of the PDF they're using (e.g. "Google_SWE_Resume.pdf"). Resume file upload (Cloudinary) is wired up in backend but not surfaced in UI.
salaryMin only (no salaryMax)UI was simplified to a single "Salary" field. salaryMax removed from schema, API, types, and charts.
AWAITING_REFERRAL statusAdded to track applications where you're waiting on a referral before formally applying.
REJECTED / GHOSTED as archiveNo separate "isArchived" column or table. These two statuses are treated as the archived state. The Applications page shows an Active tab (excludes them) and an Archived tab (shows only them). Moving a REJECTED app back to APPLIED immediately returns it to the active list.

Notification System
📅
Interview Reminder (FOLLOW_UP)
Fires 12 hours before a scheduled interview round. triggerDate = scheduledDate − 12h (pure UTC arithmetic — timezone-correct for all users). Created/replaced whenever an application or round is saved. Only created if the trigger time is still in the future.
⏳
Awaiting Referral Reminder (AWAITING_REFERRAL_REMINDER)
Fires 48 hours after status is set to AWAITING_REFERRAL. triggerDate = now + 48h. The 48h clock does not reset if you edit notes or other fields — only resets if you change status away and back. If status changes to anything else, the pending reminder is cancelled immediately.
🔔
Delivery
In-app only. No emails or push notifications. Frontend polls GET /api/notifications every 60 seconds. Endpoint returns only records where triggerDate ≤ now. Bell icon in Navbar shows unread count. Full Notifications page in sidebar shows all with mark-read and delete.
🗑️
Daily Cleanup Cron
Runs daily at 00:00 UTC via node-cron. Deletes read notifications older than 30 days. Keeps DB size in check.

Where generateNotificationsForApplication is called

  • application.controller.ts — createApplication, updateApplication
  • round.controller.ts — addRound, updateRound, deleteRound
  • Each call first deletes future FOLLOW_UP notifications for that application, then recreates from current rounds. AWAITING_REFERRAL_REMINDER is only created if none already exists (no duplicate clock reset).

Auth Flow

1
POST /api/auth/login with email + password
2
Server bcrypt-compares password, returns { token, user }
3
Zustand stores token in memory + persists to localStorage
4
Every fetch adds Authorization: Bearer <token> header
5
401 → localStorage.removeItem('token') → redirect /login

Add Application Flow

1
User fills ApplicationForm and clicks Save
2
React Hook Form's handleSubmit validates + calls onSubmit
3
POST /api/applications → Zod validates body → Prisma creates row
4
generateNotificationsForApplication schedules any relevant notifications
5
React Query invalidates ['applications'] → table refreshes

Edit Application Flow

1
Click Edit in table row
2
updateApp.reset() clears any prior error, modal opens with defaultValues
3
appliedDate converted to YYYY-MM-DD for the date input
4
On save, extra fields (id, userId, createdAt…) stripped before PUT request
5
PUT /api/applications/:id → Zod partial validates → Prisma updates

User clicks Sun/Moon icon in Navbar
2
Zustand theme.store toggles isDark, persists to localStorage
3
data-theme="dark|light" set on <html> element

Design Decisions
DecisionWhy
Native fetch over axiosaxios caused blank screen in Vite 7 due to module-level initialisation at build time. Native fetch wrapper in api.ts does everything needed: auth header injection, 401 redirect, 204 handling.
Zod on backend only, no client-side ZodReact Hook Form handles required/type checks on the client. Full Zod validation lives on the backend as the authoritative gate. Keeps the frontend bundle smaller.
CSS custom properties for themingTailwind dark mode variants require PurgeCSS to know which classes exist. CSS variables let all components use the same class names (bg-[var(--bg-surface)]) and switch via a single attribute on <html>.
React Query for server state, Zustand only for client stateAvoids duplicating server data in Zustand. Mutations call invalidateQueries to refetch rather than manually patching cached state — simpler and less error-prone.
prisma db push (no migrations)For a personal project with one developer, migration files add overhead without benefit. prisma db push syncs schema to DB directly. If schema diverges in prod, push manually before deploying.
Notifications pre-scheduled at write timeNo background worker needed. When data is saved, triggerDate is computed and stored. The GET endpoint filters by triggerDate ≤ now, making delivery "free" — just a DB filter.
"Build Resume" as external linkResume upload (Cloudinary) is wired in the backend but the UI was simplified. The sidebar links to a separately hosted resume builder project instead of managing PDFs inside this app.
Inline status dropdown in tableAvoids opening the full edit modal just to change status. StatusSelect component fires useUpdateApplication on change and updates the badge immediately via optimistic local state.
Archive via status filter (no new DB column)REJECTED and GHOSTED are the archived states. getApplications controller uses status NOT IN by default and status IN when archived=true is passed. No schema migration, no boolean flag — status is already the right signal.
Mobile-first layout: Sidebar → BottomNavAdding a responsive breakpoint to the existing Sidebar (hidden md:flex) keeps the desktop layout unchanged. A new BottomNav component (md:hidden) fixed to the bottom of the screen gives mobile users 5-tab navigation including the Resume Builder link. Bottom padding on main content (pb-20) prevents the nav from covering content.
PWA via vite-plugin-pwaConfigured in vite.config.ts with registerType: 'autoUpdate'. Auto-generates sw.js and manifest.webmanifest at build time. Requires HTTPS (Vercel in prod) for the browser to offer "Add to Home Screen". In local dev (HTTP) the manifest loads but install is blocked by browsers — test via Chrome DevTools → Application tab.
Bug Log — Issues Encountered & Fixed
fix
CORS blocked all API requests
Cause: Backend CLIENT_URL was set to port 5173, but Vite was running on 5174.
Fix: Updated CLIENT_URL in backend/.env to http://localhost:5174.
fix
New application not saving — Zod validation failure
Cause: Form sent empty string "" for workLocation (was an enum, rejected "") and resumeId (UUID format, rejected "").
Fix: Changed workLocation from enum to String in schema. Added .or(z.literal('')) to resumeId Zod field.
fix
Backend crashing silently — "Unexpected end of JSON input"
Cause: Gemini API key was invalid/missing. The Gemini call threw an unhandled promise rejection which crashed the entire Node process. Frontend received nothing back and errored with "Unexpected end of JSON input".
Fix: Added API key presence guard + full try/catch around the Gemini call in the controller.
fix
Edit modal immediately showed "[object Object]"
Cause (1): updateApp mutation error from a previous failed save was still in state when the modal opened. Cause (2): Zod validation errors are objects like { fieldErrors: {...} } — passing them to new Error(object) produces "[object Object]" as the message.
Fix (1): Call updateApp.reset() before setEditApp(app) when Edit is clicked. Fix (2): Check typeof data.error === 'string' in api.ts before constructing the Error.
fix
Edit save failing — "Request failed"
Cause: React Hook Form includes all defaultValues fields in handleSubmit output, even unregistered ones. The full Application object (with id, userId, createdAt, jdRaw: null, jobUrl: null, etc.) was being sent. Zod rejected jobUrl: null (schema only allowed string URL or "") and jdRaw: null (schema only allowed string, not null).
Fix: Strip non-form fields (id, userId, createdAt, updatedAt, interviewRounds, jdSummary, resume) in handleUpdate before sending. Added .nullable() to jobUrl and jdRaw in Zod schema.
fix
Delete interview round not reflected in UI
Cause: useDeleteRound and useUpdateRound only invalidated ['rounds', id] cache. ApplicationDetail uses useApplication which has query key ['application', id]. Wrong cache was being cleared.
Fix: Added invalidateQueries(['application', id]) to both useDeleteRound and useUpdateRound.
fix
Runtime error after adding interview time field
Cause: The import line was changed from fmtDate to fmtDateTime, but app.appliedDate in the same component still used fmtDate. TypeScript missed this because the tsc check had already passed before the change.
Fix: Import both fmtDate and fmtDateTime from dates.ts.
fix
Adding interview round did not create a notification
Cause: round.controller.ts never imported or called generateNotificationsForApplication. All three round operations (add, update, delete) had no notification side effects.
Fix: Added generateNotificationsForApplication call in addRound, updateRound, and deleteRound controllers.
fix
salaryMax still present throughout codebase
Cause: UI was simplified to a single Salary field (salaryMin only), but salaryMax was never removed from Zod schema, create/update controllers, stats controller, frontend types, and SalaryChart.
Fix: Removed salaryMax from all locations. Changed SalaryChart to use min only. Updated Stats type.
fix
StatusSelect crash — "statuses is not defined"
Cause: When adding the archive feature, the statuses array was split into activeStatuses and archivedStatuses for the filter dropdown. But StatusSelect (the inline dropdown in each table row) still referenced the old statuses variable, which no longer existed. TypeScript did not catch it because the variable had been module-scoped and tsc was satisfied.
Fix: Added allStatuses = [...activeStatuses, ...archivedStatuses] and used that in StatusSelect so all 7 statuses remain selectable, including moving an archived app back to an active status.
infra
Port 3001 EADDRINUSE on backend restart
Cause: ts-node-dev auto-restart after prisma generate clashed with itself, or a previous process was not cleaned up.
Fix: Added a predev script to backend/package.json — lsof -ti:3001 | xargs kill -9 2>/dev/null || true — which automatically clears the port before every npm run dev.
